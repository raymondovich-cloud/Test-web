# Исправление обновления тестовой версии LifeGame в Safari

- **Дата:** 10.10.2026
- **Время:** 01.01 MSK (UTC+03:00)
- **Пользовательский запрос:** исправить ситуацию, когда обычное обновление открытой вкладки Safari не применяет новую тестовую сборку, а приватный режим показывает её.
- **Изменённые файлы:**
  - `.github/workflows/deploy-pages.yml` — Version 1.1 → 1.2.
- **Причина:** добавление build-id к CSS/JS помогает только после загрузки свежего HTML. Если браузер отдаёт ранее закэшированный `index.html`, он продолжает ссылаться на старые URL ресурсов; Service Worker не перехватывает HTML-навигацию.
- **Решение:** в каждую публикуемую страницу внедряется проверка `PREVIEW_BUILD.txt` с `cache: "no-store"`. При обнаружении новой сборки страница автоматически перезагружается с уникальным параметром `lg-build`, обходящим прежний URL HTML. Проверка выполняется при загрузке, при возвращении вкладки в активное состояние и раз в 60 секунд.
- **Устойчивость:** недоступность файла версии не блокирует приложение. CI проверяет наличие ключевых элементов механизма перед публикацией. Существующий Service Worker и пользовательские данные не меняются.
- **Границы:** изменён только управляющий workflow тестового репозитория `Test-web/main`. `LifeGame/main` не затрагивается; источник продолжает собираться из `LifeGame/feature/pwa-static-cache`.
- **Проверка:** после коммита необходимо подтвердить успешные build/deploy jobs и проверить обновление в обычной вкладке Safari. Для первого получения страницы с механизмом проверки может понадобиться один раз открыть ссылку с новым query-параметром; последующие сборки должны обнаруживаться автоматически.
- **Статус:** IMPLEMENTED — механизм добавлен в pipeline; итоговая проверка ожидает завершения публикации.
